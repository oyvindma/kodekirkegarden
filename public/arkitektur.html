Arkitektur

🪦 Kodekirkegården

En AI-agent som graver i et ekte repo, og en animasjon som viser hva den gjør, mens den gjør det.

Node.js, ingen rammeverkClaude APIServer-Sent EventsCanvas, ingen byggesteg

Bruk pilene ← → eller mellomrom for å bla.

01 · Oversikt

Stort bilde

Modellen rører aldri disken selv. Den kan bare be om verktøy, og verktoy.js er det eneste som leser filer.

Én retning av gangen

Nettleseren starter en kjøring med ett GET-kall. Etter det går alt server → nettleser som en strøm av hendelser.

Samme agent overalt

npm start (terminal) og npm run web bruker samme kjørAgent. Bare emit er ulik.

02 · Agentløkka

Hele «agent-greia» er en løkke

Spør modellen, kjør verktøyene den ber om, send resultatene tilbake, gjenta til modellen svarer uten å be om verktøy.

Feil er ikke slutten

Kaster et verktøy, går feilmeldingen tilbake som tool_result med is_error. Modellen kan rette seg (f.eks. feil filsti).

Kostnadstak

MAX_ITERASJONER (standard 40) stopper en agent som går i ring. Lukker du nettleseren, avbrytes den via AbortSignal.

Funn leveres underveis

registrer_funn kalles med begrav eller la_staa, nekrolog og begrunnelse.

03 · Verktøyene

Fem verktøy, ett sted

Alle ligger i src/verktoy.js. Beskrivelsen i hver definisjon er det modellen leser for å vite når verktøyet skal brukes.

🔍 sok_i_repo tekst/regex

Søker i alle filer. Svarer «fil:linje: tekst», maks 50 treff. Fyller filer[] i hendelsen, så gravene lyser opp.

📖 les_fil fil

Leser én fil med linjenumre. Stien valideres mot ../. Agenten går til gravsteinen.

🔗 finn_referanser navn

Hele ord, utenom definisjonen. Null treff sier fra at indirekte bruk (config, dynamisk import) må sjekkes.

🕰 hent_git_historikk fil

Dato, forfatter og melding fra data/git-logg.json. Gir «sist rørt av Mona i 2021».

📜 registrer_funn leveranse

Agentens svar til systemet: fil, tittel, dom, nekrolog, begrunnelse. Frontend begraver eller tenner lykt.

Tryggheter

  • Stier valideres med path.relative
  • Treff og tekst er begrenset
  • Verktøy kan ikke skrive til disk

06 · Synk

Backend og animasjon går i hvert sitt tempo

Agenten kan levere svar på millisekunder, men det tar sekunder å gå over kirkegården. Derfor kjører frontend en hendelseskø.

HendelseAnimasjonVarighet (×1)
tanketaleboble over agenten + loggføring1,1–3 s
kall med filagenten går til gravsteinengange + 0,5 s
kall uten filring-puls rundt agenten0,5 s
svarresultat i panelet; treff-filer lyser opp0,8–1,2 s
funngå til steinen → gravhaug eller grønn lyktgange + 1,8 s
ferdigobduksjonsrapport1,2 s

Rekkefølgen er garantert

Tellere og logg følger animasjonen, ikke nettverket. Fart ×1/×2/×4 kjører flere update() per bilde.

Pause og Stopp

Pause fryser bare animasjonen, backend fyller køen videre. Stopp lukker EventSource og avbryter agenten og kostnaden.

07 · Frontend

Hvordan kirkegården tegnes

Verden bygges av de faktiske filene i repoet. Ingen bilder, alt tegnes på ett canvas.

Gravsteinens tilstand

  • Grå stein: ikke vurdert ennå
  • Gravhaug med blomst: funn med begrav
  • Grønt lys: funn med la_staa
  • Ikoner under navnet: verktøy brukt på filen

Lag i hver ramme

  • Bakgrunn, måne, stjerner
  • Soner (mapper) og gravsteiner
  • Agent, taleboble, puls-ringer
  • Tåke og flaggermus
  • Mørke med «hull» rundt lykta

Sikkerhet i UI

All tekst fra filer og modell går gjennom HTML-escape før den vises, så innhold ikke kan injisere HTML.

Sikkerhet og grenser

  • Lytter bare på 127.0.0.1. Nøkkelen sendes aldri til nettleseren.
  • Én kjøring om gangen (HTTP 429 ellers).
  • Stier valideres mot ../ og søskenmapper.
  • MAX_ITERASJONER og avbrudd ved lukket fane begrenser kostnad.
  • Agentens vurderinger må kontrolleres av et menneske før noe slettes.

Utvid

Nytt verktøy: legg { definisjon, kjør } i verktøy.   Ny hendelse: emit({type}) i agent.js + case i begin().   Annet repo: endre REPO og GIT_LOGG.
